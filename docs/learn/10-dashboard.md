# فصل ۱۰ — پنل: طراحی، توکن‌ها و تم

## هدف این فصل

ببینید یک رابط کاربری «حرفه‌ای» بیشتر از رنگ و فونت، یک **سیستم** است: توکن‌ها، چند کامپوننت پایه، حالت‌های بارگذاری و خالی و خطا، و دسترس‌پذیری. و ببینید چطور کل ظاهر پنل بدون بازنویسی صفحه‌ها عوض شد.

## مسئله: رنگ‌های پراکنده

پنل اولیهٔ این پروژه رنگ‌ها را مستقیم در کلاس‌ها داشت: `text-zinc-300`، `bg-white/5`، `bg-[#1b1b1c]`، `text-rose-200`. حدود ۴۰۰ جا. نتیجه:

- تم روشن تقریباً غیرممکن بود (`text-zinc-300` روی زمینهٔ سفید خوانا نیست).
- تغییر رنگ اصلی یعنی جست‌وجو و جایگزینی در ده‌ها فایل.
- «قرمز» یک جا `rose-200` بود، جای دیگر `rose-300`.

## راه‌حل: توکن معنایی

به‌جای «چه رنگی؟» بپرسید «این رنگ چه **نقشی** دارد؟». `web/app/globals.css`:

```css
:root, :root[data-theme="dark"] { --fg: 236 237 243; --muted: 138 143 165; --danger: 244 114 128; ... }
:root[data-theme="light"]        { --fg: 17 19 30;    --muted: 94 99 122;   --danger: 200 44 64;   ... }
```

و `web/tailwind.config.js`:

```js
const token = (name) => `rgb(var(--${name}) / <alpha-value>)`;
colors: { fg: token("fg"), muted: token("muted"), danger: token("danger"), ... }
```

چرا مقدار به شکل `236 237 243` و نه `#ecedf3`؟ تا Tailwind بتواند شفافیت اضافه کند: `bg-danger/10` می‌شود `rgb(var(--danger) / 0.1)`. با هگز این ممکن نبود.

بعد یک اسکریپت کوچک (`tokens.py` در فرایند توسعه) همهٔ کلاس‌های خام را به توکن نگاشت کرد: `zinc-300 → fg-2`، `rose-* → danger`، `white/5 → fg/5`. یعنی صفحه‌ها تقریباً دست نخوردند و کل پنل یک‌باره دوتمه شد. این قدرت یک لایهٔ انتزاع درست است.

## دو رنگ برای یک «بنفش»

`accent` و `brand` هر دو نیلی‌اند ولی جدا. چرا؟ دکمهٔ اصلی پس‌زمینهٔ نیلی با متن سفید دارد؛ رنگی که پشت متن سفید خوانا است (تیره‌تر) روی زمینهٔ تیرهٔ پنل به‌عنوان **متن** خوانا نیست. پس `accent` برای پر کردن و `brand` (روشن‌تر در تم تیره، تیره‌تر در تم روشن) برای متن و آیکون. این همان چیزی است که سیستم‌های طراحی بزرگ «on-color» یا «foreground/background pair» می‌نامند.

## تم بدون فلش

اگر تم را در `useEffect` ری‌اکت اعمال کنید، صفحه یک لحظه با تم پیش‌فرض رندر می‌شود و بعد عوض می‌شود (FOUC). راه‌حل: یک اسکریپت کوچک **داخل `<head>`** قبل از هر رندری اجرا می‌شود (`web/lib/theme-script.ts`)، انتخاب ذخیره‌شده یا ترجیح سیستم‌عامل را می‌خواند و `data-theme` را روی `<html>` می‌گذارد.

یک باگ واقعی هنگام ساخت همین: ابتدا ثابت `THEME_SCRIPT` و hook `useTheme` در یک فایل بودند. `layout.tsx` یک **Server Component** است و import کردن فایلی که `useState` دارد در آن، build را شکست داد. راه‌حل: جدا کردن ثابت (بدون React) در `theme-script.ts` از hook کلاینتی در `theme.ts`. درس: در App Router، مرز server/client را در سطح **فایل** طراحی کنید.

## چند کامپوننت، همه‌جا

`web/components/ui.tsx` حدود پانزده کامپوننت دارد (`Button`، `Card`، `FormSection`، `StatusBadge`، `Empty`، …). قاعده: صفحه‌ها رنگ نمی‌سازند، کامپوننت ترکیب می‌کنند. وقتی `StatusBadge` همهٔ وضعیت‌های API را به چهار تُن (`live`، `busy`، `bad`، `idle`) نگاشت می‌کند، «در حال ساخت» در لیست اپ‌ها، جزئیات اپ و تاریخچه دقیقاً یک شکل است.

## حالت‌ها مهم‌تر از حالت خوشحال

بیشتر وقت کاربر صرف «صبر کن»، «هنوز چیزی نیست» و «خطا شد» می‌شود:

- **بارگذاری**: skeleton هم‌شکل محتوای نهایی، نه spinner وسط صفحه. `lib/api.ts` یک کش در حافظه دارد تا برگشت به صفحهٔ قبل فوری باشد و در پس‌زمینه تازه شود.
- **خالی**: `Empty` توضیح می‌دهد این لیست برای چیست و قدم بعد را پیشنهاد می‌کند.
- **خطا**: پیام `detail` خود API عیناً نشان داده می‌شود؛ پس API باید پیام‌های قابل فهم بدهد («Saved, but could not be applied to the container: …»).
- **کار خطرناک**: `confirmAction` روی دکمهٔ «انصراف» فوکوس می‌کند تا یک Enter اشتباهی چیزی را پاک نکند.

## دسترس‌پذیری از اول

- همهٔ عناصر تعاملی `:focus-visible` دارند (از توکن accent).
- `Tabs` نقش `tablist/tab`، `Choice` نقش `radiogroup/radio`، `Toggle` نقش `switch` و `Meter` نقش `meter` دارد.
- آیکون‌ها `aria-hidden`؛ دکمه‌های فقط‌آیکون `aria-label` دارند.
- وضعیت هیچ‌وقت فقط با رنگ گفته نمی‌شود (badge متن دارد).
- `prefers-reduced-motion` انیمیشن‌ها را خاموش می‌کند.
- لینک «Skip to content» برای کاربران کیبورد.

## از راست‌به‌چپ به چپ‌به‌راست

نسخهٔ اولیه فارسی و RTL بود. برای تبدیل، فقط `dir` عوض نشد: هر کلاس فیزیکی (`right-3`، `pr-9`، `text-right`) و هر آیکون جهت‌دار (chevron «برگشت» و «ورود به جزئیات») جداگانه بررسی شد. درس برای پروژهٔ بعدی: از اول کلاس‌های **منطقی** (`ps-`، `pe-`، `start-`، `end-`) استفاده کنید تا هر دو جهت رایگان کار کنند.

## تمرین

1. یک توکن جدید `--highlight` اضافه کنید و `StatusBadge` را طوری تغییر دهید که وضعیت `deploying` با آن رنگ شود. در هر دو تم امتحان کنید.
2. نسبت کنتراست `--muted` روی `--bg` را در هر دو تم با یک ابزار (مثلاً WebAIM) حساب کنید. حداقل WCAG AA برای متن معمولی چند است؟
3. در `useTheme` حالت `system` را دنبال کنید: اگر کاربر وسط کار تم سیستم‌عامل را عوض کند چه می‌شود؟ کدام خط این را مدیریت می‌کند؟
4. `node e2e/screenshots.cjs` را اجرا کنید (فصل ۱۲) و یک خطای کنسول عمداً اضافه کنید. اسکریپت چه می‌کند؟
